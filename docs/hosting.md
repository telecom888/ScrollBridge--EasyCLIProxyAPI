# 托管与同名模型路由

ScrollBridge 可以同时使用本地 EasyCLIProxyAPI 和多个托管密钥。托管来源属于具体账号，**不是**协议类型。一个账号提供的模型停用或删除，不应影响其他账号的相同模型。

## 配置托管密钥

打开左侧「托管」，点击「添加密钥」。选择 OpenAI、Anthropic、Google 或 Vertex AI，填写账号名称与 API Key。Vertex AI 还需填写 Google Cloud Project ID 和 Location。你可以添加多个相同协议的账号，并随时查看、修改、启停、复制或删除密钥。

OpenAI、Anthropic、Google 可通过「获取模型」取得可访问的官方模型目录，再选择添加。Vertex AI 的 Model Garden 列表接口需要 Google OAuth 2.0，使用本机 ADC，例如先运行 `gcloud auth application-default login`。**Vertex 的服务账号绑定 API Key 不能直接读取 Model Garden 列表**，如未配置 ADC 可使用手动添加模型。目录列出模型不代表该账号必然有调用权限。

## 公开模型和供应来源

API 地址独立于协议选择，可填写第三方兼容服务、自定义端口和路径前缀，支持 HTTP/HTTPS。例如 OpenAI 地址为 `https://example.com/proxy/v1` 时，模型目录和对话分别请求 `/proxy/v1/models` 和 `/proxy/v1/chat/completions`。地址末尾已有 API 版本时不会重复拼接；未填写版本时使用对应协议的默认版本。URL 中不填写密钥、查询参数或片段，密钥使用单独输入框。

「设置」有两个独立开关：

- **显示模型来源**：在「模型」页面及权限选择器中显示具体托管 Key 名称；本地源显示「本地代理」。不在模型列表里使用供应商图标。
- **同名模型统一路由**：关闭时，不同托管账号对外使用各自唯一的 `host-...` 前缀模型 ID。开启时，相同真实模型 ID 的来源可以统一对外显示为一个 ID。

在「托管 → 同名模型路由」标签中管理每个模型的来源优先级。默认按已有本地模型与托管模型的添加顺序排列。按「上移」「下移」可以调整优先顺序，修改自动保存。禁用或删除某来源后，其余可用来源继续参与路由。

当较高优先级的来源在**响应尚未交给客户端之前**明确返回 HTTP 401、403、404、429 或 5xx，系统会依次尝试下一可用来源。如果网络中断导致请求是否执行不确定，或者 SSE 已经开始输出，则不会重新发送生成请求。即使是明确错误，前一个上游也可能产生费用，因此请给不同账号分别设置额度。

## 接口范围

托管适配器支持 OpenAI Chat Completions、Anthropic Messages 和 Gemini GenerateContent 的文本对话及流式响应。不同协议之间的文本消息、系统提示和基本输出长度会按目标协议转换；原生相同协议请求在支持范围内尽可能直接传递。工具调用、复杂多模态输入、语音、图片生成及 WebSocket 等跨协议操作暂不在托管适配器范围内，不能依靠模型名推测兼容性。原本由本地代理提供的接口和权限功能保持不变。

## 图表与本地数据

「记录 → 图表」展示三小时内、六小时内、二十四小时内、当天、一周内和一月内的模型调用量柱状图。每次通过模型鉴权的请求只计一次，路由故障切换不会重复统计。数据按分钟聚合在本机 `call-stats.json` 文件中，不存储提示词、模型名称或上游密钥。使用原有的 AES 格式加密，数据超过 31 天会在定期清理、读取或应用退出时移除。

**安全提示：** ScrollBridge 原有 AES 实现使用应用内置固定密钥，主要提供混淆和篡改检测，而不是操作系统级的保密边界；任何可以提取程序中的固定密钥并读取文件的人，仍可能恢复内容。不要把这些配置文件当作具有独立 Windows 凭据隔离的秘密保险箱。

## 旧版本配置

配置格式升级为 v4。v3 会通过 `lib/store-migrations.cjs` 只在内存中补齐托管字段，第一次保存时才写入 v4；原有对外密钥、模型别名及权限保持不变。旧版无法读取 v4 时会拒绝加载，不会悄悄丢掉托管字段。建议升级前备份配置文件，避免需要回退时缺少原始 v3 备份。
